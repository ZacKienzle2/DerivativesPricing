At the core of nearly all Monte Carlo simulations is a sequence of apparently random numbers used to drive the simulation. In analysing Monte Carlo methods, we will treat this driving sequence as though it were genuinely random. This is a convenient fiction that allows us to apply tools from probability and statistics to analyse Monte Carlo computations. It is convenient because modern Pseudo-random number generators are sufficiently good at mimicking genuine randomness to make this analysis informative. Nevertheless, we should be aware that the apparently random numbers at the heart of a simulation are, in fact, produced by completely deterministic algorithms.

Because a random number generator may be called thousands or even millions of times in a single simulation, it must be fast.

Before discussing sequences that appear to be random but are not, we should specify what we mean by a generator of genuinely random numbers: we mean a mechanism for producing a sequence of random variables $U_1, U_2, \dots$ with the property that
\begin{enumerate}[(i)]
	\item each $U_i$ is uniformly distributed between 0 and 1;
	\item the $U_i$ are mutually independent.
\end{enumerate}

Property (i) is a convenient but arbitrary normalisation; values uniformly distributed between 0 and 1/2 would be just as useful, as would values from nearly any other simple distribution. Uniform random variables on the unit interval can be transformed into samples from essentially any other distribution. Property (ii) is the more important one. It implies, in particular, that all pairs of values should be uncorrelated and, more generally, that the value of $U_i$ should not be predictable from $U_1, \dots, U_{i-1}$.

A random number generator (often called a \textit{pseudo-random} number generator to emphasise that it only mimics randomness) produces a finite sequence of numbers $u_1, u_2, \dots, u_K$ in the unit interval. Typically, the values generated depend in part on input parameters specified by the user. \textit{Any} such sequence constitutes a set of possible outcomes of independent uniforms $U_1, \dots, U_K$. A good random number generator satisfies the admittedly vague requirement that small (relative to $K$) segments of the sequence $u_1, \dots, u_K$ should be difficult to distinguish from a realisation of independent uniforms.

An effective generator, therefore, produces values that appear consistent with properties (i) and (ii) above. If the number of values $K$ is large, the fraction of values falling in any sub-interval of the unit interval should be approximately the length of the sub-interval; this is uniformity. Independence suggests that there should be no discernible pattern among the values. To put this only slightly more precisely, statistical tests for independence should not easily reject segments of the sequence $u_1, \dots, u_K$.

Most random number generators at present are based on linear recurrence relations. One of the most important random number generators is the \textit{multiple-recursive generator} (MRG) of \textit{order $k$}, which generates a sequence of integers $X_k, X_{k+1}, \dots$ via the linear recurrence
\begin{equation} \label{eq:MRGRecurrence}
	X_t = (a_1 X_{t-1} + \dots + a_k X_{t-k}) \bmod m, \quad t = k, k+1, \dots
\end{equation}
for some \textit{modulus} $m$ and \textit{multipliers} $\{a_i, i = 1, \dots, k\}$. Here ``$\bmod$'' refers to the modulo operation: $n \bmod m$ is the remainder when $n$ is divided by $m$. The recurrence is initialised by specifying $k$ ``seeds'', $X_0, \dots, X_{k-1}$. To yield fast algorithms, all but a few of the multipliers should be 0. When $m$ is a large integer, one can obtain a stream of pseudo-random numbers $U_k, U_{k+1}, \dots$ between 0 and 1 from the sequence $X_k, X_{k+1}, \dots$, simply by setting $U_t = X_t/m$. It is also possible to set a small modulus, in particular $m=2$. The output function for such \textit{modulo 2 generators} is then typically of the form
\begin{equation} \label{eq:Modulo2OutputFunction}
	U_t = \sum_{i=1}^w X_{tw+i-1} 2^{-i}
\end{equation}
for some $w \le k$, e.g., $w=32$ or $64$. Examples of modulo 2 generators are the \textit{feedback shift register generators}, the most popular of which are the \textit{Mersenne twisters}.



MRGs with excellent statistical properties can be implemented efficiently by combining several simpler MRGs and carefully choosing their respective moduli and multipliers. One of the most successful is L'Ecuyer's \texttt{MRG32k3a} generator, see \citep{lecuyerGoodParametersImplementations1999}.

\begin{Pcode}{mrg32k5a.py}
	M1, M2, NORM = 4294949027.0, 4294934327.0, 2.3283163396834613e-10
	A12, A14, A15 = 1154721.0, 1739991.0, 1108499.0
	A21, A23, A25 = 1776413.0, 865203.0, 1641052.0

	state = np.random.SeedSequence(42).generate_state(10).astype(np.float64)
	s1, s2, out = state[:5], state[5:], np.empty(1000, dtype=np.float64)

	for i in range(1000):
	p1 = (A12 * s1[2] + A14 * s1[1] - A15 * s1[0]) % M1
	s1[:-1], s1[-1] = s1[1:], p1

	p2 = (A21 * s2[4] + A23 * s2[2] - A25 * s2[0]) % M2
	s2[:-1], s2[-1] = s2[1:], p2

	out[i] = (p1 - p2 + M1) * NORM if p1 <= p2 else (p1 - p2) * NORM
\end{Pcode}

Simulating a random variable $X$ from an arbitrary (that is, not necessarily uniform) distribution invariably involves the following two steps.
\begin{algorithm}[H]
	\caption{Simulation of Random Variable $X$}
	\label{alg:SimulationRandomVariableX}
	\begin{algorithmic}[1]
		\State Simulate uniform random numbers $U_1, \dots, U_k$ on $(0, 1)$ for some $k = 1, 2, \dots$
		\State Return $X = g(U_1, \dots, U_k)$, where $g$ is some real-valued function.
	\end{algorithmic}
\end{algorithm}

\subsection{Simulating Random Variables}

\subsubsection{Inverse-Transform Method}
Let $X$ be a random variable with cumulative distribution function (cdf) $F$. Let $F^{-1}$ denote the inverse\footnotetext{Every cdf has a unique inverse function defined by $F^{-1}(u) = \inf\{x : F(x) \ge u\}$. If, for each $u$, the equation $F(x) = u$ has a unique solution $x$, this definition coincides with the usual interpretation of the inverse function.}  of $F$ and $U \sim \U(0, 1)$. Then,
\begin{equation}
	\Prob[F^{-1}(U) \le x] = \Prob[U \le F(x)] = F(x).
\end{equation}

This leads to the following method to simulate a random variable $X$ with cdf $F$:

\begin{algorithm}[H]
	\caption{Inverse-Transform Method}
	\begin{algorithmic}[1]
		\Require Cumulative distribution function $F$.
		\Ensure Random variable $X$ distributed according to $F$.
		\State Generate $U$ from $\U(0, 1)$.
		\State $X \gets F^{-1}(U)$
		\State \Return $X$
	\end{algorithmic}
\end{algorithm}

\begin{xtip}
	The inverse-transform method is applicable to both continuous and discrete distributions. After importing \code{numpy} as \code{np}, simulating numbers $0, \dots, k - 1$ according to probabilities $p_0, \dots, p_{k-1}$ can be done via \code{np.min(np.where(np.cumsum(p) > np.random.rand()))}, where \code{p} is the vector of the probabilities.
\end{xtip}

\subsubsection{Acceptance-Rejection Method}
The acceptance-rejection method is used to sample from a ``difficult'' probability density function (pdf) $f(x)$ by generating instead from an ``easy'' pdf $g(x)$ satisfying $f(x) \le C g(x)$ for some constant $C \ge 1$ (for example, via the inverse-transform method), and then accepting or rejecting the drawn sample with a certain probability. \cref{alg:AcceptanceRejection} gives the pseudo-code.

The idea of the algorithm is to generate a point $(X, Y)$ under the graph of the function $Cg$ uniformly, by first drawing $X \sim g$ and then $Y \sim \U(0, Cg(X))$. If this point lies under the graph of $f$, then we accept $X$ as a sample from $f$; otherwise, we try again. The efficiency of the acceptance-rejection method is usually expressed in terms of the probability of acceptance, which is $1/C$.

\begin{algorithm}[H]
	\caption{Acceptance-Rejection Method}
	\label{alg:AcceptanceRejection}
	\begin{algorithmic}[1]
		\Require Pdf $g$ and constant $C$ such that $Cg(x) \ge f(x)$ for all $x$.
		\Ensure Random variable $X$ distributed according to pdf $f$.
		\State found $\gets$ \textbf{false}
		\While{\textbf{not} found}
		\State Generate $X$ from $g$.
		\State Generate $U$ from $\U(0, 1)$ independently of $X$.
		\State $Y \gets U C g(X)$
		\If{$Y \le f(X)$}
		\State found $\gets$ \textbf{true}
		\EndIf
		\EndWhile
		\State \Return $X$
	\end{algorithmic}
\end{algorithm}

\subsection{Simulating Random Vectors and Processes}
\lettrine[lines=2, lhang=0.1]{T}{echniques} for generating random vectors and processes are as diverse as the class of random processes themselves. We highlight a few general scenarios.

When $X_1, \dots, X_n$ are \textit{independent} random variables with pdfs $f_i, i = 1, \dots, n$, so that their joint pdf is $f(\bx) = f_1(x_1) \cdots f_n(x_n)$, the random vector $X = [X_1, \dots, X_n]^\top$ can be simply simulated by drawing each component $X_i \sim f_i$ individually, for example, via the inverse-transform method or acceptance-rejection.

For \textit{dependent} components $X_1, \dots, X_n$, we can, as a consequence of the \textit{product rule} of probability, represent the joint pdf $f(\bx)$ as
\begin{equation} \label{eq:JointPdfProductRule}
	f(\bx) = f(x_1, \dots, x_n) = f_1(x_1) f_2(x_2 | x_1) \cdots f_n(x_n | x_1, \dots, x_{n-1}),
\end{equation}
where $f_1(x_1)$ is the marginal pdf of $X_1$ and $f_k(x_k | x_1, \dots, x_{k-1})$ is the conditional pdf of $X_k$ given $X_1 = x_1, X_2 = x_2, \dots, X_{k-1} = x_{k-1}$. Provided the conditional pdfs are known, one can generate $X$ by first generating $X_1$, then, given $X_1 = x_1$, generate $X_2$ from $f_2(x_2 | x_1)$, and so on, until generating $X_n$ from $f_n(x_n | x_1, \dots, x_{n-1})$.

\subsubsection{Normal Random Variables and Vectors}
Normal random variables are the building blocks of many financial simulation models

$$ \Phi(x) \coloneqq \mathbb{P}(X \le x) = \frac{1}{\sqrt{2\pi}} \int_{-\infty}^{x} e^{-y^2 / 2} dy, \quad x \in \mathbb{R}, $$

denotes the standard Gaussian Cumulative Distribution Function (CDF) of a standard normal random variable $X \simeq \mathcal{N}(0,1)$, which posits the relation

\begin{equation}
	\Phi(-x) = 1 - \Phi(x), \quad x \in \mathbb{R}.
\end{equation}

\begin{algorithm}[H]
	\caption{Normal Random Vector Simulation}
	\label{alg:NormalVectorSim}
	\begin{algorithmic}[1]
		\Require Mean vector $\bmu$, Covariance matrix $\bSigma$
		\Ensure Random vector $\bX \sim \mathcal{N}(\bmu, \bSigma)$
		\State Compute Cholesky decomposition $\bSigma = \bB\bB^\T$
		\State Generate standard normal vector $\bZ \sim \mathcal{N}(\mathbf{0}, \mathbf{I})$
		\State $\bX \gets \bmu + \bB\bZ$
		\State \Return $\bX$
	\end{algorithmic}
\end{algorithm}

\begin{Pcode}{BivariateNormal.py}
	rng = np.random.default_rng(4)
	N, rhos = 1000, [0.0, 0.8]
	Z = rng.standard_normal((2, N))
	Ls = [np.linalg.cholesky([[1, r], [r, 1]]) for r in rhos]
	Xs = [L @ Z for L in Ls]
\end{Pcode}
